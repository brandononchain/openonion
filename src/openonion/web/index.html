Settings

Model

The model is the part that thinks. OpenOnion works with any server that speaks the OpenAI API, including ones running on this computer, or with Anthropic.

Start from

Fills in the provider and address. Your key and model choice stay as they are.

Provider

Usually ends in /v1. Unsloth, Ollama, LM Studio, vLLM and llama.cpp all work.

Pick a model that supports tool calling, or the agent can chat but can't act.

Connectors

Connect apps and services that speak MCP (Model Context Protocol). The agent only sees the few tools that match what you ask, and can look up more while it works.

Connectors run with their own access, and their traffic doesn't go through Tor. In Tor-only and offline chats, connectors that reach the internet are switched off. Only add ones you trust.

Fewer keeps the model focused. It can still search for others.

Tor

Each conversation gets its own Tor connection, so separate chats can't be linked by their traffic. These settings point OpenOnion at the Tor service.

A range like 9100-9109 allows 10 private chats at once.

Safety

Limits that apply to every conversation. Each chat also has its own network mode and "Ask before changes" chip on the message box.

Let the agent run commandsAdds a shell tool inside the workspace. It always asks first. Leave this off unless you need it.
Show browser windowsOpens a visible browser when the agent browses. Only useful when OpenOnion runs on your own desktop.

After this, the agent skips the action.

Server

These come from the environment OpenOnion was started with, and change only with a restart.

Settings you save here are stored in on the server, readable only by the account OpenOnion runs as. They take priority over environment variables. Keys are never sent back to the browser.
